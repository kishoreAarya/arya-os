## 2. BLOCKER-1 CLOSURE EVIDENCE (CWD ISOLATION)

### Identified Defect in Phase 3.2.4.4.0
In Phase 3.2.4.4.0, `OpenMontageAdapter._run_subprocess()` invoked `asyncio.create_subprocess_exec()` without specifying the `cwd` parameter. Consequently, the child process inherited the working directory of the AryaOS backend server process (`arya-os-v1/backend`), creating potential path traversal risks, relative file collisions, and pollution of server workspace root.

### Code Verification in Phase 3.2.4.4.1
In [`backend/app/services/openmontage_adapter.py`](file:///Users/venkatakishorenasina/Documents/arya-os-v1/backend/app/services/openmontage_adapter.py#L668-L677):
```python
proc = await asyncio.create_subprocess_exec(
    *cmd,
    stdin=asyncio.subprocess.PIPE,
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
    env=clean_env,
    cwd=str(self.openmontage_path),
    start_new_session=True,
)
```

### Specific Verifications
1. **Explicit CWD Parameter:** `asyncio.create_subprocess_exec()` explicitly receives `cwd=str(self.openmontage_path)`. `self.openmontage_path` is resolved upon initialization (`Path(...).resolve()`).
2. **Server Working Directory Isolation:** The backend server working directory cannot become the child process CWD. Even when the caller server CWD changes dynamically, the child process is pinned to `openmontage_path`.
3. **Relative Output Path Resolution:** Relative output paths generated by OpenMontage resolve strictly relative to OpenMontage's execution root or designated output directory, never the server root.
4. **Immunization from User Input Overrides:** Neither `execute_tool()` nor `_run_subprocess()` accepts a user-controlled working directory parameter. Action inputs (`inputs_json`) are passed strictly as JSON string payloads over `stdin` to the sandboxed Python runner script.
5. **Path Traversal Protection:** Any attempts to navigate parent directories (`../`) within artifact paths or output locations are intercepted by `validate_artifact_file()` via strict string matching and `.resolve()` boundary verification against the storage directory.
6. **Process Group Isolation:** Subprocesses are launched with `start_new_session=True`, creating a dedicated POSIX session/PGID. Termination via `terminate_process_tree()` dispatches `os.killpg(pid, signal.SIGTERM)` followed by `SIGKILL`, ensuring all descendant processes are reaped without orphaned leaks.

## 3. BLOCKER-2 CLOSURE EVIDENCE (SUBPROCESS ENVIRONMENT ISOLATION)

### Identified Defect in Phase 3.2.4.4.0
In Phase 3.2.4.4.0, the subprocess environment was constructed using `os.environ.copy()`, exposing all AryaOS backend secrets (`DATABASE_URL`, `POSTGRES_PASSWORD`, `SECRET_KEY`, `MASTER_API_KEY`, etc.) to child processes spawned for tool execution.

### Code Verification in Phase 3.2.4.4.1
In [`backend/app/services/openmontage_adapter.py`](file:///Users/venkatakishorenasina/Documents/arya-os-v1/backend/app/services/openmontage_adapter.py#L578-L634):
```python
def build_subprocess_env(self, tool_name: str) -> dict[str, str]:
    clean_env: dict[str, str] = {}

    # 1. Inherit only explicitly allowed safe system variables
    for key in SAFE_SYSTEM_ENV_ALLOWLIST:
        if key in os.environ:
            clean_env[key] = os.environ[key]

    # 2. Guarantee required runtime variables fail closed or have safe fallbacks
    if "PATH" not in clean_env:
        clean_env["PATH"] = os.defpath or "/usr/local/bin:/usr/bin:/bin"

    if "HOME" not in clean_env:
        user_home = os.environ.get("HOME") or os.environ.get("USERPROFILE")
        clean_env["HOME"] = user_home if user_home else "/tmp"

    # 3. Add OpenMontage virtualenv bin directory to PATH
    venv_bin = str(self.python_path.parent)
    if venv_bin not in clean_env["PATH"].split(os.pathsep):
        clean_env["PATH"] = f"{venv_bin}{os.pathsep}{clean_env['PATH']}"

    # 4. Inject tool-specific provider credentials ONLY for external API tools
    if is_external_tool(tool_name):
        try:
            from app.core.config import get_settings
            s = get_settings()
            fal_k = s.fal_key or s.fal_api_key or os.environ.get("FAL_KEY") or os.environ.get("FAL_API_KEY")
            if fal_k:
                clean_env["FAL_KEY"] = fal_k
                clean_env["FAL_API_KEY"] = fal_k
            kling_k = getattr(s, "kling_api_key", None) or os.environ.get("KLING_API_KEY")
            if kling_k:
                clean_env["KLING_API_KEY"] = kling_k
        except Exception:
            pass

    # 5. Defense-in-depth: Strictly purge forbidden secrets
    for forbidden in FORBIDDEN_SECRET_KEYS:
        clean_env.pop(forbidden, None)

    return clean_env
```

### Specific Verifications
1. **Zero Blanket Inheritance:** `os.environ.copy()` is completely eliminated. `clean_env` starts as an empty dictionary `{}`.
2. **Explicit System Allowlist:** Only variables in `SAFE_SYSTEM_ENV_ALLOWLIST` (such as `PATH`, `HOME`, `LANG`, `TMPDIR`, `BLENDER_PATH`, `FFMPEG_PATH`) can be populated.
3. **Strict Exclusion of Backend Secrets:**
   - `DATABASE_URL` — Never passed.
   - `POSTGRES_PASSWORD`, `POSTGRES_USER`, `POSTGRES_DB` — Never passed.
   - `SECRET_KEY`, `JWT_SECRET` — Never passed.
   - `MASTER_API_KEY`, `SYSTEM_MASTER_KEY`, `DEVELOPMENT_BYPASS_KEY` — Never passed.
   - Unrelated provider keys (`AWS_SECRET_ACCESS_KEY`, `STRIPE_SECRET_KEY`, `OPENAI_API_KEY`, `GITHUB_TOKEN`) — Never passed.
4. **Conditioned External Provider Keys:** `FAL_KEY` and `KLING_API_KEY` are injected only when `is_external_tool(tool_name)` returns `True`. Local tools (`camera_motion`, `local_diffusion`, `blender_world`, etc.) do not receive any provider keys.
5. **User Input Immunization:** `build_subprocess_env()` takes only `tool_name: str`. It does not accept user inputs, preventing injection of `LD_PRELOAD`, `PYTHONPATH`, or arbitrary variables.
6. **Zero Environment Logging:** Child environment dictionaries are never logged or exposed. All subprocess logs, diagnostics, and stderr outputs pass through `sanitize_text()`.

## 4. BLOCKER-3 CLOSURE EVIDENCE (PHYSICAL ARTIFACT VALIDATION)

### Identified Defect in Phase 3.2.4.4.0
In Phase 3.2.4.4.0, action nodes could transition to `SUCCEEDED` based purely on in-memory dictionary outputs returned by the provider adapter without validating whether actual physical media files existed on disk or contained valid media bytes.

### Code Verification in Phase 3.2.4.4.1
Two-layer defense-in-depth physical validation was established:
1. **Layer 1: Provider Dispatcher Validation Hook** in [`backend/app/services/dispatcher.py`](file:///Users/venkatakishorenasina/Documents/arya-os-v1/backend/app/services/dispatcher.py#L568-L626).
2. **Layer 2: Autonomous Execution Runner Authoritative Gate** in [`backend/app/services/autonomous_execution_runner.py`](file:///Users/venkatakishorenasina/Documents/arya-os-v1/backend/app/services/autonomous_execution_runner.py#L682-L723).
3. **Core Validation Engine** in [`backend/app/services/artifact_validator.py`](file:///Users/venkatakishorenasina/Documents/arya-os-v1/backend/app/services/artifact_validator.py#L83-L398).

### Disk Checks Enforced Before `SUCCEEDED`
1. **File Existence:** Resolves absolute path and verifies `resolved_path.is_file()`. Missing file immediately fails validation.
2. **Regular File & Directory Confinement:** Enforces `str(resolved_path).startswith(str(resolved_dir))` to prevent directory escapes.
3. **Filename Safety:** Validated against `^[a-zA-Z0-9_\-\.]+$` with explicit rejection of `..`, `/`, and `\`.
4. **Non-Zero Size & Upper Size Limits:** Empty 0-byte files fail validation. Upper limits are strictly enforced:
   - Images: `MAX_IMAGE_SIZE_BYTES = 50 MB`
   - Videos: `MAX_VIDEO_SIZE_BYTES = 500 MB`
5. **Binary Magic Bytes:**
   - PNG: `\x89PNG\r\n\x1a\n`
   - JPEG: `\xff\xd8\xff`
   - WEBP: `RIFF....WEBP`
   - MP4: `ftyp` box within first 32 bytes
   - WEBM: `\x1a\x45\xdf\xa3`
6. **Rejection of Text/HTML Masquerades:** Explicitly scans header bytes for `<!DOCTYPE`, `<html`, `<?xml`, `{"error"`, `{"detail"`, `Error 404`, `Error 500`.
7. **Deep Media Integrity Verification:**
   - Images: Verified via Pillow (`Image.open()`, `im.verify()`, format strictly in `PNG`, `JPEG`, `WEBP`, width > 0, height > 0).
   - Videos: Verified via `ffprobe` JSON stream analysis (valid video stream, positive width/height, valid container).
8. **SHA-256 Checksumming:** Computed directly from disk bytes and attached to the validation result.

## 6. ARTIFACT VALIDATION TRACE

The full trace from OpenMontage tool result to database persistence was audited:

```
[ OpenMontage Subprocess ]
       │ Emits protocol v1.1 framed JSON: {"artifacts": ["/path/to/media.png"]}
       ▼
[ openmontage_adapter._run_subprocess ]
       │ Extracts and parses single authentic v1.1 frame
       │ Normalizes into OpenMontageToolResult(artifacts=[...])
       ▼
[ LiveProviderDispatcher.dispatch ]
       │ 1. Resolves relative artifact paths against self.output_dir
       │ 2. Calls validate_artifact_file(target_art_path, allowed_dir=self.output_dir)
       │ 3. If validation fails:
       │      Returns ExecutionResult(success=False, status="FAILED", error=art_val.error)
       │    If validation succeeds:
       │      Returns ExecutionResult(success=True, status="SUCCEEDED", artifacts=[...])
       ▼
[ AutonomousExecutionRunner.dispatch_action ]
       │ 1. Re-locks action node with with_for_update()
       │ 2. Verifies worker lease fencing token and epoch
       │ 3. If exec_result.status == "FAILED":
       │      Transitions node status -> FAILED
       │      Persists outputs_json and sanitized error
       │ 4. If exec_result.status == "SUCCEEDED":
       │      Defense-in-depth: Re-verifies validate_artifact_file() on disk
       │      If invalid: Transitions node status -> FAILED
       │      If valid: Transitions node status -> SUCCEEDED
       │ 5. Commits transaction to database
       ▼
[ AutonomousExecutionRunner.evaluate_dag_readiness ]
       │ Inspects prerequisite statuses for all child action nodes
       │ Any prerequisite in ("FAILED", "BLOCKED", "SKIPPED") -> child marked "BLOCKED"
       │ Result: Downstream nodes CANNOT transition to READY or EXECUTING
```
